# Contributing to JobMatcher Frontend

Thank you for considering contributing to JobMatcher! We welcome contributions from everyone.

## Code of Conduct

This project and everyone participating in it is governed by the [JobMatcher Code of Conduct](CODE_OF_CONDUCT.md). By participating, you are expected to uphold this code.

## How to Contribute

### Reporting Bugs

1. Check the [issue tracker](https://github.com/Tushaar01-hub/JobMatcher/issues) to see if the bug has already been reported.
2. If not, create a new issue with a clear title and description.
3. Include as much relevant information as possible.
4. Include steps to reproduce the bug.
5. Include screenshots or screen recordings if applicable.

### Suggesting Enhancements

1. Check the [issue tracker](https://github.com/Tushaar01-hub/JobMatcher/issues) to see if the enhancement has already been suggested.
2. If not, create a new issue with a clear title and description.
3. Explain why the enhancement would be useful.
4. Include any relevant mockups or examples.

### Pull Requests

1. Fork the repository and create your branch from `main`.
2. If you've added code that should be tested, add tests.
3. Ensure your code follows the project's coding standards.
4. Update the documentation if necessary.
5. Make sure your code passes all tests.
6. Issue the pull request with a clear title and description.

## Development Setup

1. Clone the repository:
   ```bash
   git clone https://github.com/Tushaar01-hub/JobMatcher.git
   cd JobMatcher/frontend
   ```

2. Install dependencies:
   ```bash
   npm install
   ```

3. Create a `.env` file based on `.env.example`:
   ```bash
   cp .env.example .env
   ```

4. Start the development server:
   ```bash
   npm run dev
   ```

5. Open your browser to `http://localhost:5173`

## Coding Standards

- Follow the existing code style in the project.
- Use meaningful variable and function names.
- Write clear, concise comments.
- Keep functions small and focused on a single task.
- Write tests for new features and bug fixes.

## Commit Guidelines

- Use clear and descriptive commit messages.
- Reference the issue number in the commit message if applicable.
- Follow the [Conventional Commits](https://www.conventionalcommits.org/) specification.

## Testing

- Run tests with:
  ```bash
  npm test
  ```

- Write new tests for new features and bug fixes.
- Ensure all tests pass before submitting a pull request.

## Code Review Process

1. Your pull request will be reviewed by a maintainer.
2. Address any feedback or requested changes.
3. Once approved, your pull request will be merged.
